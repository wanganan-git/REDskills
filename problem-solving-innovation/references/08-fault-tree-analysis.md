# 故障树分析（Fault Tree Analysis, FTA）

## 一句话定义
从不期望发生的顶层事件出发，用树状逻辑图逐层向下分解所有可能的原因组合，通过逻辑门（与/或）量化各因素的贡献度。

## 核心原理与步骤

**原理：**
五问法是单链追问，故障树是多分支穷举。它从"发生了什么坏事"出发，用逻辑门把所有可能的故障路径画出来，适合分析复杂的、多因素交织的系统性故障。

**核心逻辑门：**

| 逻辑门 | 符号 | 含义 |
|--------|------|------|
| OR（或门） | ∨ | 任一输入事件发生，输出就发生 |
| AND（与门） | ∧ | 所有输入事件同时发生，输出才发生 |

**操作步骤：**
1. **定义顶事件** — 明确你要分析的不期望事件（系统级故障）
2. **第一层分解** — 什么原因能直接导致顶事件？用OR门或AND门连接
3. **逐层深入** — 对每个中间事件继续分解，直到基本事件（不可再分的底层故障）
4. **定性分析** — 找出最小割集（导致顶事件发生的最小基本事件组合）
5. **定量分析** — 如果有故障率数据，计算顶事件发生概率
6. **制定对策** — 针对关键路径制定预防或缓解措施

**符号说明：**
- 矩形：事件（需要继续分解的中间事件）
- 圆形：基本事件（不再分解的底层原因）
- 菱形：未展开事件（暂不深入分析的原因）

## 适用场景
- 安全关键系统分析（航空、核电、医疗设备）
- 复杂系统的可靠性评估
- 重大事故的根因调查（空难、爆炸、数据泄露）
- 产品设计阶段的失效模式预防
- 需要量化风险概率的场景

## 实操案例
**顶事件：** 用户数据泄露

```
        [用户数据泄露]
              |
        ┌───OR───┐
        ↓        ↓
   [外部攻击] [内部泄露]
        |        |
    ┌──OR──┐   ┌──OR──┐
    ↓      ↓   ↓      ↓
 [SQL注入] [钓鱼] [员工误操作] [权限过大]
    |      |       |         |
   ┌OR┐    |     ┌OR┐      ┌OR┐
   ↓  ↓    ↓     ↓  ↓      ↓  ↓
 [无输入校验] [无MFA] [无培训] [无最小权限]
```

**分析结果：**
- 最小割集：{无输入校验}、{无MFA}、{无培训}、{无最小权限}
- 这四个基本事件任一发生，都可能导致数据泄露
- 优先级：无输入校验 > 无最小权限 > 无MFA > 无培训

**对策：**
- 加输入校验（技术措施，成本低，阻断SQL注入路径）
- 实施最小权限原则（管理措施，限制内部泄露影响范围）
- 强制MFA（技术措施，阻断钓鱼攻击路径）
- 安全培训（长期措施，降低人为失误概率）

**关键洞察：** 故障树和五问法互补——五问法适合单链深挖，故障树适合多因素系统分析。对于复杂系统故障，先用故障树画出全局，再用五问法对关键分支深挖。故障树最大的价值是让你看到：同一结果可能有完全不同的原因路径，不能只盯着最显眼的那条。
