# 提示词最佳实践与避坑指南

本文档收录使用 AI 工具时的常见错误、避坑技巧和增效策略。

---

## 一、必检查清单

### 1. @ 引用检查

**问题**: 上传了素材（图/视频），但提示词里忘记用 `@` 引用，导致模型不会使用这些素材。

**解决方案**:

| 检查项 | 说明 |
|--------|------|
| [ ] 所有上传的素材都已用 `@` 引用 | 确保每个素材都被使用 |
| [ ] `@` 后的名称与素材名称一致 | 避免拼写错误 |
| [ ] `@` 引用位置合理 | 放在提示词中合适的位置 |

**示例**:

❌ **错误**:
```
请根据这张图片生成一个视频...
```

✅ **正确**:
```
请根据 @首帧图片 生成一个视频...
```

---

### 2. 视频延长选对时长

**问题**: 延长视频时选择过长的生成时长，导致多生成无用内容。

**原则**: 延长 5 秒就选 5 秒的生成时长，选长了会多生成无用内容。

**示例**:

| 需求 | 应选择的时长 | 错误选择 |
|------|-------------|---------|
| 延长 5 秒 | 5 秒 | 10 秒、15 秒 |
| 延长 3 秒 | 3 秒或 5 秒 | 10 秒 |

**原因**: AI 会按照你指定的时间长度生成内容，选长了会浪费 token 和时间。

## 二、增效技巧

### 3. 多生成几次（抽卡）

**问题**: AI 生成有随机性，第一次不满意就放弃。

**策略**: 同样的提示词多跑几次（2-5次），挑选最好的结果。

**为什么有效**:
- AI 的生成有概率性
- 每次生成可能略有不同
- 多次生成可以获得更满意的结果

**建议**:
- 简单任务：2-3 次
- 复杂任务：5-10 次
- 重要内容：10+ 次

**示例流程**:

```
第1次生成：→ 不满意，调整提示词
第2次生成：→ 有进步，记录好的部分
第3次生成：→ 很好，保存
第4次生成：→ 更好，替换之前的
...
```

---

### 4. 先简单后复杂

**问题**: 新手一开始就叠加视频参考、音频参考等复杂功能，导致效果不佳。

**建议**: 从"一张图 + 文字描述"开始，熟悉后再叠加复杂功能。

**渐进式学习路径**:

| 阶段 | 内容 | 目标 |
|------|------|------|
| **第1阶段** | 纯文字提示词 | 理解基本指令 |
| **第2阶段** | 文字 + 1张图片 | 学习图文结合 |
| **第3阶段** | 文字 + 多张图片 | 学习多素材协调 |
| **第4阶段** | 文字 + 图片 + 视频参考 | 学习风格迁移 |
| **第5阶段** | 所有素材组合 | 综合运用 |

**示例**:

❌ **新手直接尝试复杂任务**:
```
"根据 @视频1 的运镜、@图片2 的色调、@音频3 的节奏，生成一个15秒的视频..."
```

✅ **从简单开始**:
```
"生成一个赛博朋克城市夜景的视频，15秒。"
→ 成功后，再逐步添加参考素材
```

### 5. 像写代码一样管理提示词

**问题**: 提示词写完就丢，无法复用和改进。

**策略**: 对重要提示词做版本控制、使用占位符、进行 A/B 测试。

#### 5.1 版本控制

**命名规范**:

```
提示词名称_v1.md
提示词名称_v2.md
提示词名称_v3_最终版.md
```

**版本记录**:

```markdown
# 产品文案提示词

## 版本历史

### v1.0 (2024-01-15)
- 初始版本
- 基础框架：CRISPE

### v2.0 (2024-01-16)
- 增加了 Few-Shot 示例
- 优化了输出格式要求

### v3.0 (2024-01-20)
- 增加了小红书风格变体
- 调整了字数限制

---

## 当前版本：v3.0
[提示词内容]
```

---

#### 5.2 使用占位符

**目的**: 让提示词可复用，只需替换变量即可。

**示例**:

```markdown
你是一名专业的{角色}。

# 任务
为{产品名称}撰写{内容类型}。

# 要求
1. 目标受众：{目标受众}
2. 字数：{字数要求}
3. 风格：{风格要求}
4. 核心卖点：{核心卖点}

# 使用时替换以下内容：
- {角色}：营销专家
- {产品名称}：智能降噪耳机
- {内容类型}：小红书文案
- {目标受众}：25-30岁都市白领
- {字数要求}：100字左右
- {风格要求}：年轻化、生活感
- {核心卖点}：40dB降噪、30h续航
```

---

#### 5.3 A/B 测试

**目的**: 对比不同提示词的效果，选择最优版本。

**测试流程**:

```markdown
# A/B 测试记录

## 测试目标
生成小红书产品文案

## 版本 A
```markdown
你是一名营销专家。请为智能降噪耳机写一篇小红书文案，100字左右。
```

## 版本 B
```markdown
你是一名擅长小红书文案的营销专家，深谙年轻化表达和生活化场景的写作技巧。
为智能降噪耳机撰写一篇吸引人的小红书营销文案，80-120字，必须包含生活化场景和emoji。
```

## 测试结果

| 版本 | 生成质量 | 风格匹配度 | 可用性 | 备注 |
|------|---------|-----------|--------|------|
| 版本 A | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐ | 简单但不够精准 |
| 版本 B | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | 效果最好 |

## 结论
采用版本 B，后续优化细节。
```

## 三、常见错误与解决方案

### 错误 1：指令模糊

**症状**: AI 的输出不符合预期，或者过于宽泛。

**原因**: 提示词不够具体，缺少明确的约束。

**解决方案**:

❌ **模糊指令**:
```
"写一篇关于环保的文章。"
```

✅ **具体指令**:
```
"写一篇关于塑料污染的文章，面向高中生读者，800字，包含：
1. 塑料污染的现状数据
2. 对海洋生态的影响
3. 个人可以采取的3个行动
用项目符号列表组织内容。"
```

---

### 错误 2：缺少上下文

**症状**: AI 的输出过于通用，不符合实际场景。

**原因**: 没有提供足够的背景信息。

**解决方案**:

❌ **缺少上下文**:
```
"优化这段代码。"
```

✅ **提供上下文**:
```
# 背景
这是一个用户画像分析模块，需要处理100万条用户数据，当前性能瓶颈在于数据库查询。

# 代码
[代码内容]

# 优化目标
- 将查询时间从5秒降低到1秒以内
- 保持代码可读性
- 不改变现有接口
```

---

### 错误 3：过度约束

**症状**: AI 的输出生硬、不自然，或者无法满足所有约束。

**原因**: 提示词中有太多相互冲突的限制。

**解决方案**:

❌ **过度约束**:
```
"写一个搞笑的故事，但要严肃认真，500字，包含10个角色，每个角色都要有完整的背景，还要有教育意义..."
```

✅ **合理约束**:
```
"写一个有幽默感的职场故事，主要角色2-3个，800字左右，主题是'新员工的成长'。"
```

---

### 错误 4：忽略输出格式

**症状**: AI 的输出格式不符合使用需求，需要大量后处理。

**原因**: 没有明确指定输出格式。

**解决方案**:

❌ **未指定格式**:
```
"分析这几个产品的优缺点。"
```

✅ **指定格式**:
```
"分析这几个产品的优缺点，请输出为Markdown表格，包含以下列：
- 产品名称
- 优点（列出3个）
- 缺点（列出2个）
- 推荐指数（1-5分）

产品列表：iPhone 15、小米14、华为Mate 60"
```

---

### 错误 5：忘记 Few-Shot 示例

**症状**: AI 的输出风格、格式不稳定。

**原因**: 没有提供示例来展示期望。

**解决方案**:

❌ **无示例**:
```
"写产品评价，要客观真实。"
```

✅ **提供示例**:
```
"写产品评价，要客观真实。

示例1：
产品：无线耳机
评价：用了两周，音质不错，降噪效果可以，但续航有点短，每天都要充电。

示例2：
产品：智能手表
评价：续航很给力，两周充一次，但心率监测不太准，和医用设备比有差距。

现在请评价：机械键盘
"
```

## 四、效率提升工具

### 1. 提示词模板库

建立自己的模板库，分类管理：

```
templates/
├── writing/           # 写作类
│   ├── 小红书文案.md
│   ├── 公众号文章.md
│   └── 邮件回复.md
├── coding/            # 编程类
│   ├── 代码审查.md
│   ├── 单元测试.md
│   └── 文档生成.md
├── analysis/          # 分析类
│   ├── 数据分析.md
│   ├── 竞品分析.md
│   └── 用户调研.md
└── creative/          # 创作类
    ├── AI生图.md
    ├── AI生视频.md
    └── 剧本创作.md
```

---

### 2. 提示词检查清单

在发送提示词前，快速检查：

```markdown
# 提示词检查清单

## 基础要素
- [ ] 任务目标清晰
- [ ] 目标受众明确
- [ ] 输出格式指定

## 上下文
- [ ] 背景信息充足
- [ ] 使用场景说明
- [ ] 已有信息提供

## 约束条件
- [ ] 长度/字数限制
- [ ] 风格/语调要求
- [ ] 必须包含的内容
- [ ] 不能包含的内容

## 优化要素
- [ ] Few-Shot 示例（2-3个）
- [ ] 角色设定
- [ ] 输出结构说明

## 技术检查
- [ ] @引用正确（如用素材）
- [ ] 占位符标记清晰
- [ ] 无矛盾要求

全部通过后再发送！
```

---

### 3. 提示词调试技巧

当 AI 输出不符合预期时：

| 问题 | 调试方法 |
|------|----------|
| **输出太简单** | 增加"请详细说明"、"请展开" |
| **输出太冗长** | 增加"请简洁"、"控制在X字以内" |
| **风格不对** | 增加 Few-Shot 示例，明确风格要求 |
| **格式不对** | 提供格式模板或示例 |
| **内容偏离** | 检查指令是否清晰，增加约束 |
| **总是出错** | 简化任务，分步骤执行 |

## 五、黄金公式总结

### 高效提示词的结构

```
@素材引用 + 用途说明 + 具体画面/任务描述 + 时间线/步骤 + 输出格式 + Few-Shot示例
```

### 完整示例

```markdown
@首帧图片 作为第一帧
参考 @视频1 的运镜和转场效果

# 任务
生成一个15秒的赛博朋克主题视频

# 时间线
0-5秒：镜头从全景缓缓推近到人物特写
5-10秒：环绕镜头展示场景全貌
10-15秒：拉镜头，定格在城市远景

# 技术参数
- 分辨率：4K
- 帧率：24fps
- 风格：赛博朋克+写实

# 示例参考
[提供1-2个类似的视频描述示例]
```

## 六、核心心法

**写提示词的本质是思维工程。**

你定义问题的清晰度，直接决定了 AI 发挥的上限。

- 不要死记硬背模板
- 要锻炼将模糊需求拆解为机器可执行指令的能力
- 把提示词当作可迭代的产品，持续优化
- 建立自己的提示词库和知识体系

---

## 七、快速参考卡

| 场景 | 必做事项 | 不要做 |
|------|---------|--------|
| **所有任务** | 明确目标、提供上下文 | 模糊指令 |
| **AI生视频/图** | 用@引用素材、指定时间线 | 忘记引用、时长选错 |
| **编程任务** | 迭代优化、先测试后实现 | 一次写完所有功能 |
| **文案创作** | 提供风格示例、明确受众 | 只说"写个文案" |
| **数据分析** | 指定输出格式、给出示例 | 只说"分析一下" |
| **学习任务** | 双层解释、逆向工程 | 只问定义 |

---

**记住：好的提示词 = 清晰的目标 + 充足的上下文 + 明确的约束 + 优质的示例**
