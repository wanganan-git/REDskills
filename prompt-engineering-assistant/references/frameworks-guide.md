# 提示词框架选择指南

本文档收录主流的提示词框架及其适用场景，帮助为不同任务选择最合适的结构。

---

## 一、通用任务设计框架

### 1. CRISPE 框架

**全称**: Context（上下文）、Role（角色）、Instruction（指令）、Scenario（场景）、Prompt（提示词）、Evaluation（评估）

**核心思想**: 通过多维度约束，减少AI"幻觉"，提高输出的精准性和场景适配性。

**要素拆解**:

| 要素 | 说明 | 示例 |
|------|------|------|
| **Context** | 提供任务背景、历史信息、领域知识 | "这是一家B2B SaaS公司的年度产品发布会文案..." |
| **Role** | 指定AI扮演的具体角色 | "你是一名拥有10年经验的产品营销专家..." |
| **Instruction** | 清晰、具体地描述需要完成的任务 | "撰写一篇产品发布会演讲稿..." |
| **Scenario** | 描述任务的实际应用场景、受众、媒介 | "受众是潜在客户和企业决策者，用于线下发布会..." |
| **Prompt** | 整合以上要素，形成最终指令，可加入示例 | "综合以上信息，写出1500字的演讲稿..." |
| **Evaluation** | 定义评估标准，用于迭代优化 | "评估标准：专业度、感染力、行动召唤清晰度..." |

**适用场景**:
- ✅ 复杂的专业任务（文案、咨询、分析）
- ✅ 需要多维度约束的场景
- ✅ 输出质量要求较高的任务

**不适用场景**:
- ❌ 简单的问答/总结任务（会过度设计）
- ❌ 需要快速迭代、试错的场景

---

### 2. OpenAI 官方六大原则

**核心思想**: 强调清晰的沟通逻辑，更偏向原则和策略。

**六大原则**:

1. **写出清晰的指令**（核心中的核心）
   - 用具体、明确的描述替代模糊表达
   - 示例：❌ "写个短文案" → ✅ "写一段50字的产品卖点文案，面向25-35岁职场女性"

2. **提供参考文本**（降低幻觉，作为知识库）
   - 给出相关资料、文档、数据
   - 示例："参考以下产品特性：...（附产品手册）"

3. **将复杂任务拆分为更简单的子任务**
   - 分步骤、分模块处理
   - 示例："先分析用户需求，再给出解决方案，最后提供实施步骤"

4. **给模型时间"思考"**（如使用链式思考 CoT）
   - 让 AI 展示推理过程
   - 示例："请先分析问题的核心，再逐步推导结论"

5. **使用外部工具**（如代码执行、搜索 API）
   - 结合工具提升能力
   - 示例："使用 Python 进行数据验证，然后给出结论"

6. **系统地测试变更**（主要用于开发优化）
   - 迭代测试，逐步优化
   - 示例："生成 3 个版本的提示词，对比效果"

**适用场景**:
- ✅ 通用任务优化（问答、总结、翻译）
- ✅ 快速原型设计
- ✅ 初学者编写提示词

**不适用场景**:
- ❌ 高度专业化的复杂任务（约束不够）
- ❌ 需要严格结构的场景

## 二、特定场景优化框架

### 3. 分层结构化框架（AI生图/生视频）

**核心思想**: 告别自然语言堆砌，采用分层、模块化的描述，让模型更易遵循。

**视频生成七层结构**:

| 层级 | 要素 | 说明 | 示例 |
|------|------|------|------|
| 1 | **Subject** | 主体（人/物及其外观特征） | "一位身穿黑色风衣的赛博朋克武士，30岁左右，面容坚毅" |
| 2 | **Action** | 动作（具体动词、速度、方向） | "缓慢拔出武士刀，刀刃反光" |
| 3 | **Environment** | 环境（背景、天气、时间） | "东京街头，暴雨夜，霓虹灯闪烁" |
| 4 | **Camera Movement** | 运镜（专业摄影术语） | "慢镜头，推镜头（Dolly In），低角度拍摄" |
| 5 | **Lighting** | 布光（光源、强度、色温） | "冷色调侧光，雨滴反射霓虹光" |
| 6 | **Atmosphere/Style** | 氛围/风格 | "赛博朋克风格，胶片感，写实风" |
| 7 | **Technical Specs** | 技术参数 | "4K分辨率，24fps，16:9宽高比" |

**图像生成类似框架**:

- **S-E-L-C 框架**: Subject（主体）, Environment（环境）, Lighting（布光）, Composition（构图）
- **工单式指令**: 强调属性精准绑定

**适用场景**:
- ✅ AI 生图（Midjourney, Stable Diffusion, DALL-E）
- ✅ AI 生视频（Runway, Pika, Sora）
- ✅ 需要精准控制画面元素的场景

**不适用场景**:
- ❌ 纯文本任务

### 4. 结构化 JSON Prompting

**核心思想**: 用 JSON 键值对强制结构化思维，替代线性自然语言。

**优势**:
- 指令模块化
- 键名即语义
- 易于解析和复用
- 适合程序化处理

**示例**:

```json
{
  "task": "generate_image_prompt",
  "subject": {
    "entity": "Cyberpunk Samurai",
    "appearance": "black trench coat, katana",
    "age": "30s"
  },
  "action": {
    "verb": "unsheathe",
    "object": "katana",
    "speed": "slow"
  },
  "environment": {
    "location": "Tokyo Street",
    "weather": "Heavy Rain",
    "time": "night"
  },
  "camera": {
    "movement": "Dolly In",
    "angle": "low angle",
    "speed": "slow motion"
  },
  "style": {
    "genre": "Cyberpunk",
    "mood": "noir",
    "quality": "photorealistic"
  },
  "negative_prompt": "blurry, low quality, distorted"
}
```

**适用场景**:
- ✅ 编程任务（API 对接、自动化流程）
- ✅ 复杂指令（多参数、多约束）
- ✅ Agent 设计（状态维护、工作流）
- ✅ 需要程序化解析的场景

**不适用场景**:
- ❌ 简单对话任务
- ❌ 非技术用户使用

### 5. 元认知与工作流框架

**核心思想**: 让 AI 在回答前进行系统性的自我推理和检查，提升答案的可靠性。

**元认知推理专家示例**:

1. **分解** (Decompose): 将问题拆分为子问题
2. **解决** (Solve): 逐一处理，并给出置信度
3. **验证** (Verify): 检查逻辑、事实、完整性、偏见
4. **综合** (Synthesize): 整合答案
5. **反思** (Reflect): 若置信度低，找出弱点重试

**长任务/Agent 框架**:
- 将 Prompt 设计成可循环的工作流
- 包含目标拆解、笔记协议、循环跳出条件、恢复流程
- 使 AI 能处理需要长时间、多步骤的复杂项目

**适用场景**:
- ✅ 需要高可靠性的分析、决策任务
- ✅ 复杂推理、数学证明、法律分析
- ✅ Agent 设计、多步骤工作流

**不适用场景**:
- ❌ 简单任务（会过度设计）
- ❌ 对延迟敏感的实时任务

## 三、框架选择决策树

```
开始
  │
  ├─ 是文本任务吗？
  │   ├─ 是 → 简单通用任务？
  │   │   ├─ 是 → OpenAI 六大原则
  │   │   └─ 否 → 复杂专业任务？
  │   │       ├─ 是 → CRISPE 框架
  │   │       └─ 否 → 需要高可靠性？
  │   │           ├─ 是 → 元认知推理框架
  │   │           └─ 否 → 返回重新评估
  │   │
  │   └─ 否 → 是图像/视频任务吗？
  │       ├─ 是 → 分层结构化框架（七层法）
  │       └─ 否 → 是编程/API任务吗？
  │           ├─ 是 → JSON 结构化
  │           └─ 否 → 根据任务特征推荐组合框架
```

## 四、组合使用策略

**没有"最好"的框架，只有"最合适"的框架**。

常见组合场景：

| 场景 | 推荐组合 |
|------|----------|
| 专业文案创作 | CRISPE + Few-Shot |
| 复杂数据分析 | OpenAI 原则（拆分任务）+ 元认知推理 |
| AI 生图工作流 | 分层结构化 + JSON 格式 |
| 高可靠性决策系统 | 元认知推理 + JSON 格式 |
| 简单问答 | OpenAI 原则（简化版） |

---

## 五、演进趋势

**从"写提示词"到"设计上下文/技能"**:

未来的趋势是 **Skill Engineering**，将领域经验、工作流沉淀为可复用的技能包（如 Claude Skills）。

- 优势: 比单个 Prompt 更强大、更可维护
- 方向: 将提示词方法论沉淀为可复用的"技能"
